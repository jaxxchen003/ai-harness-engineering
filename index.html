SECTION 01

Harness 不是模型，不是提示词，也不完全是框架

2025–2026 年，三个方向独立收敛到同一个结论：Mitchell Hashimoto 的失败驱动定义、LangChain 的 Viv Trivedy 的分类学、以及 Anthropic 与 OpenAI 的生产报告——多数 agent 失败是配置与 harness 的失败，不是模型的失败。

“模型负责思考，agent 负责行动，harness 负责不让 agent 像个傻子一样行动。” —— 对 harness 的一句式概括（dev.to 社区综述）

运行层定义

harness 是位于模型与真实世界之间的一切：重试逻辑、状态管理、上下文处理，以及工作流崩溃后的恢复机制。

工程脚手架定义

围绕语言模型的工程支架，把它变成可靠的 agent：它能看到的上下文、能调用的工具、不可逾越的权限边界、运行环境，以及衡量一次运行的评测。

Anthropic 的三分法

Claude Managed Agents 把系统拆成三件：Session（只追加的事件日志）+ Harness（无状态控制循环，调用模型并路由工具）+ Sandbox（隔离执行环境）。“容器是牲口，不是宠物。”

2026 年的写作还把四个层次叠起来看：prompt engineering（告诉模型什么）→ context engineering（它应该看到什么）→ agent engineering（它的角色与工具有哪些）→ harness engineering（整个系统如何运转）。近来热议的 loop engineering（反复的“工作—反馈”循环）是 harness 工程内部的一层。

SECTION 02

核心十层：拆开任何一个 harness 都在看这些

Arize 对 Hermes 的审计给出了九要素清单（外层迭代循环、上下文管理与压缩、技能与工具管理、子 agent 管理、内置技能、会话持久与恢复、系统提示组装与项目上下文注入、生命周期钩子、权限与安全层）——与下面的十层划分基本同构。

01

模型路由

多供应商适配、按任务选模型（强规划者 / 廉价执行者）、配额耗尽时降级、努力等级。Claude Code 只用 Claude（订阅 / Bedrock / Vertex / Foundry）；OpenCode、Pi、Hermes、DeepSeek Harness 是多供应商 + 本地 Ollama。

02

工具使用

少而精、类型明确、失败模式安全的工具。光谱两端：Pi 的 4 个工具与 Claude Code 约 40–45 个、DeepSeek Harness 约 53 个内置工具。工具越少，模型花在“选工具”上的推理与 token 越少。

03

沙箱 / 执行环境

操作系统级强制（Seatbelt、Landlock、bubblewrap+seccomp、Docker、受限令牌）还是只靠提示词。Codex 与 DeepSeek Harness 把它当架构问题；Pi 与 Hermes 明确拒绝把进程内限制伪装成沙箱。

04

权限 / 审批

声明式 allow / ask / deny 规则集与权限模式。能阻断工具调用的 hook，是唯一不依赖模型注意力的强制手段。

05

上下文 / 记忆管理

指令文件（CLAUDE.md / AGENTS.md / HERMES.md / SOUL.md）、按需加载的技能、带血缘的压缩、会话持久化（SQLite、只追加事件日志）、用文件与 git 承载跨窗口状态。

06

规划与任务分解

规划工具（Deep Agents 的 write_todos）、特性清单（feature-list.json，初始全部 passes:false）、以及动态工作流——由主 agent 现场生成一段 JS 编排程序。

07

验证 / 测试

测试、lint、类型检查作为回喂循环的“传感器”；独立的评估者 agent；“测试棘轮”（永不删除或改坏失败的测试来蒙混过关）；浏览器自动化做端到端检查。

08

可观测 / 日志

轨迹、转录、会话日志、token 与成本核算、allow/deny 决策审计。看不见 agent 做过什么，就无法修复、信任或解释它。

09

多 agent 编排

上下文隔离的子 agent、每人一个 worktree / 分支、协调者 + 执行者、共享记忆与目标。代价：每个子 agent 都烧 token 且让验证更难——委派是为了隔离，不只是并行。

10

人在环中

不可逆动作的审批门、不阻塞工作的提问卡、运行中途的纠偏、以及对 diff / PR 的最终人工审查。HumanLayer 的立场：质量判断仍归人；agent 只会为“测试通过”优化，不会为可维护性优化。

案例库：十个被点名的 harness 逐个拆解

星数为 2026 年 10 月二手汇总的快照，不同来源互相冲突，文中给出区间——请把它们当作“采用热度”而非精确计数。好评与批评均转述自所引述的评测文章，非本报告实测。

Claude CodeAnthropic · 参照系 harness

编程闭源2025 年 5 月发布

专有 agentic 编程 CLI（另有 IDE / 桌面 / Web 界面），只跑 Claude 模型（也经 Bedrock、Google Agent Platform、Microsoft Foundry）。它是所有人逆向工程的对象。

架构：约 40+ 工具（Read / Edit / Grep / Glob / Bash 等核心）；CLAUDE.md（也读 AGENTS.md）作项目记忆；技能（.claude/skills/<name>/SKILL.md）；子 agent（.claude/agents/，独立上下文、工具与权限）；MCP 服务器；.claude/settings.json 中的钩子（PreToolUse 可阻断、Stop 可把住出口）；插件把以上全部打包；worktree；上下文压缩；五种权限模式（default / acceptEdits / plan / auto / bypassPermissions，其中 bypass 只应在隔离容器 / VM 里用）。会话可从转录恢复；云端会话跑在 Anthropic 托管沙箱并可直接建 PR。

多 agent（2026）：子 agent 之外还有 Agent Teams（组长 + 队友、共享任务列表、各自上下文）、Claude Code Projects（2026 年 9 月 17 日改版：协调者 + 并行云端线程，各自独立分支 / 仓库副本，共享记忆、目标与资料库，冲突以 git 合并冲突形式呈现）、Dynamic Workflows（主 agent 写一段 JS 工作流程序，最多拉起约 1,000 个子 agent，按模型分工，worktree 隔离）。

好评扩展系统最深（钩子 / 技能 / 插件）；长时运行配方最成熟（见第 7 节）；深度多文件工作的共识之选。
批评闭源，无法 fork 或审计循环本身；系统提示大（对比中约 10–14k token，Pi 不到 1k）；bypassPermissions 是“会上新闻”的模式；本地运行默认无容器隔离。
技术栈：Node.js CLI许可：专有闭源官方层：Claude Agent SDK、Claude Managed Agents

“Claude Work”查无此独立产品 · 三件真实的事

名称澄清多 agent

本次调研未能核实存在官方名为 “Claude Work” 的产品。这个说法背后对应三件互不相同、各自可核实的事情，引用时切勿混为一谈。

① Anthropic 真正的多 agent“工作”概念：就是上一条的 Projects / Agent Teams / Dynamic Workflows——协调者 + 执行线程、共享记忆、git 分支隔离。

② 社区在 Claude Code 之上搭的多 agent 脚手架：如 GStack（开源仓库，用技能把 Claude Code 变成一支“AI 工程团队”：Office Hours、对抗评审、Design Shotgun）；以及著名的 16 个 Claude 编译器实验（16 个实例、约 2,000 个会话、约 2 万美元，每个实例在独立 Docker 容器中，用文件锁抢任务，冲突时 git rebase）。

③ 一个名称撞车，必须提醒读者：claude-work 也是一种 shell 别名写法（CLAUDE_CONFIG_DIR=~/.claude-work），用于切换第二个 Claude 账号——是多账号技巧，不是多 agent 产品。

相关的官方层：Claude Agent SDK（“按我们造 Claude Code 的方式造你自己的”运行时）与 Claude Managed Agents（托管版：Session / Harness / Sandbox 三分，0.08 美元 / 会话小时 + token 计费，凭据经出口代理隔离在沙箱之外，官方称 p50 首 token 延迟改善约 60%、p95 约 90%）。

结论：写作与引用时，请具体指明 Projects、Agent Teams、社区脚手架或多账号别名中的哪一个

托管的、产物优先（artifact-first）的设计 harness：聊天 + 实时画布，画布与导出 / 交接本身就是验证回路。

官方产品：2026 年 4 月 17 日以研究预览上线（后转 beta，一家追踪站称 2026 年 10 月 8 日脱离 beta），入口 claude.ai/design，面向 Pro / Max / Team / Enterprise；发布时由 Claude Opus 4.7 驱动，后加入模型选择。可通过聊天、行内评论、直接编辑、生成的滑杆来精修；输入支持文本、图片、DOCX / PPTX / XLSX、截图、网页捕获、GitHub 仓库与设计系统导入；导出 PDF、PPTX、独立 HTML、Canva，并可生成交接包给 Claude Code。它明确不是 Figma 的替代（没有像素级组件系统），而是补充。

OpenAI Codexopenai/codex · Apache-2.0

编程开源约 119–129k 星（快照）

开源（Rust 引擎）的终端 / IDE / 桌面 / 云端 / GitHub 机器人 harness，与 GPT-5.x-Codex、GPT-6.x 模型协同设计。沙箱即架构。

三大接入面（2026 年“Codex as a Platform”）：codex exec（有界的脚本化任务 / CI）、Codex SDK（编程式启动 / 恢复 / 流式）、app-server（持久会话状态、事件流、工具暴露、审批处理——你的应用管业务逻辑、MCP、审批与 UI，Codex 管循环与沙箱执行）。

标志性设计：每条命令都在操作系统监狱里跑（macOS Seatbelt、Linux bubblewrap+seccomp），文件系统限定在工作区，网络默认关闭；模型可以把“提权”作为工具 schema 的一部分正式申请；沙箱与审批策略分开配置。以 shell + apply_patch 为主；最新模型上，一个 JS 运行器工具让模型写脚本在内部组合工具（更少往返、更少 token），且运行在密封沙箱中。上下文压缩 + 保留推理在一处引用对比中把 ARC-AGI-3 从 13.3% 提到 38.3%，输出 token 约降到 1/6。

好评多篇对比中原始编程能力最强；token 效率最高（号称少用 2–3 倍）；有真正的安全模型。
批评模型闭源且按 OpenAI 的节奏弃用；云端不可选模型；钩子 / 技能 / 插件生态比 Claude Code 年轻；离开 OpenAI 模型就不是最佳状态。

OpenCodeAnomaly（原 SST 团队）· MIT

编程开源约 202–222k 星（快照）

终端优先（Bubble Tea TUI），另有桌面应用（beta）与各 IDE 扩展（经 ACP）。模型无关：经 Models.dev 接 75+ 供应商，也可本地跑 Ollama / LM Studio / llama.cpp，还能用 GitHub Copilot 或 ChatGPT Plus/Pro 账号登录。

标志性设计——客户端 / 服务器：后台服务器持有 AI 通信与会话状态（本地 SQLite），TUI、桌面、IDE 都只是客户端，SSH 断线会话不丢。两个内置 agent 用 Tab 切换：Build（全权限）与 Plan（默认只读：拒绝编辑，执行 bash 前先问）。另有 @general 通用子 agent；编辑后回喂 LSP 诊断；git 快照支持 /undo 撤销重做；MCP 客户端（含 OAuth 远程服务器）；可分享的会话链接；CI 模式（在 GitHub issue / PR 里用 /opencode）。权限是按工具的 allow / ask / deny 数据，不是写死的模式。

好评供应商独立；隐私好（除非选云模型，代码不出本机）；可按任务混搭模型。
批评质量取决于你选的模型；配置量比商业工具大；出问题自己修；桌面端仍是 beta；Build 默认偏宽松（默认只拦重复的相同调用与项目外路径）。

DeepSeek Harness（dsh）DeepSeek 官方 · MIT · 开发者预览

编程 / 通用开源2026 年 8 月 13 日发布

“一切皆插件”：在 Cordis 组合框架上，模型适配器、工具注册表、会话日志、乃至 agent 循环本身都是可替换插件，没有特权核心。

架构：插件可干净地增删（副作用可完全撤销）；四种模式（Standard / Minimal / Code / Creator）；供应商覆盖 Anthropic、OpenAI、Bedrock、Azure、Gemini Enterprise、DeepSeek 及任意 OpenAI 兼容网关；内置 Claude Code / Codex 子 agent 供应商（默认关闭）；只追加事件日志 → 恢复 / 分叉 / 重放 / 转录；沙箱为 Landlock（Linux）/ Seatbelt（macOS）/ 受限令牌运行器（Windows）；hooks.json 与 Claude / OpenAI 互通；MCP 客户端；Markdown 配置；一处审计数出 53 个内置工具。供应商广度上它复用了 Pi 的模型层。安装：npx @deepseek-ai/dsh web（本地 127.0.0.1:3080）。

采用速度：星数报道按日期剧烈冲突（一天 74,578、48 小时约 95k、8 月底约 203k、10 月初约 242–247k，均为二手来源）——“本组中增长最快”这一轨迹有多源印证，确切数字没有。

好评可组合性走到了极致：连循环都可换；多供应商与本地网关友好；事件日志让恢复与审计成为默认能力。
批评 / 警示开发者预览，官方明示会有破坏性变更且未经安全审计；其安全声明亦称沙箱“降低但不保证隔离”——应在一次性 VM 中以最小权限运行。一项被引用的研究（腾讯朱雀实验室，14,560 条轨迹）测得间接提示注入成功率按渠道最高 25.5%。v0.2 桌面端（2026 年 10 月）官方覆盖 macOS / Windows，Linux 只有社区构建。

SECTION 07

从业者在 X 与长文里真正达成的共识

词源先说清，有两位“命名者”：Mitchell Hashimoto 在 2026 年 2 月 5 日《My AI Adoption Journey》中写道——“我不知道业界有没有公认的词，我已经管这叫 harness engineering 了：每当你发现 agent 犯了一个错，你就花时间工程化地解决它，让它永不再犯。”Ghostty 的 AGENTS.md 每一行都源于 agent 真实犯过的一次错——它是一份失败日志，不是愿望清单。LangChain 的 Viv Trivedy 随后（2 月 17 日、3 月 10 日）在 X 上给出分类学与那句传播最广的话：“一个编程 agent = 模型 + 它周围的 harness，harness 干了大部分活。”（其长文据报道达 73.3 万浏览、4,800 收藏）TheDeepFeed 的判语是：“Mitchell 命了名，Viv 是分类学家。”归属之外，还有一句反方声音值得并列：LlamaIndex 的 Jerry Liu 认为脚手架时代正在坍缩、上下文质量才是护城河。

1

薄 harness，厚技能

老一代框架想把所有聪明都塞进 harness——上万 token 的系统提示。新做法反过来：harness 保持薄（一个小而干净、透明的循环），真正的专业知识住在技能里——外部的、可发现的、按需加载的知识包。harness 是操作系统，技能是应用。

2

“这不是模型问题，是配置问题”

HumanLayer 的 Kyle Mistele《Skill Issue》的六件套：更好的指令、更多的能力、隔离的子任务执行、生命周期自动化、自我验证，外加规划者 / 执行者分离与类型检查反压。

3

确定性工具优先于提示词

一句可直接套用的分工口诀：“必须每次都发生、绝不能漏的，是 hook；要读很多文件的，是子 agent；只在某些时候适用的，是技能。”钩子是保证，CLAUDE.md 只是建议——“钩子是唯一不依赖模型注意力的强制手段。”

4

测试驱动的 agent 循环

Anthropic 2026 年 3 月的规划者 → 生成者 → 评估者三分，存在的理由就一句：“模型给自己的作业打分总是过于慷慨。”Stripe 的 Minions（大型单仓库生产实践）则是：蓝图（前馈式架构指引）+ 推送前传感器钩子（lint / 类型 / 测试，agent 在人看到之前先自我纠正）+ 一次性执行。

5

写循环，不要写提示词

Claude Code 负责人 Boris Cherny（2026 年 6 月，Acquired Unplugged）：“我已经不给 Claude 写提示词了。我让循环去提示 Claude、去判断该做什么。我的工作是写循环。”OpenClaw 作者 Peter Steinberger 在 X 上（2026 年 6 月 7–8 日）：“你不该再提示编程 agent 了。你应该设计去提示你的 agent 的循环。”（据一家账号统计达 650 万浏览）Addy Osmani 随后将其命名为 loop engineering；其积木是：自动化 / 定时、worktree、技能、MCP 连接器、子 agent、外部状态。

6

Ralph Wiggum 循环

Geoffrey Huntley 2025 年的土法炼钢：while 循环里把同一份 PROMPT.md 喂给全新会话，直到出现完成承诺 / 测试通过；状态活在文件与 git 历史里，而不是一条越拉越长的上下文里。Anthropic 后来把它做成官方 ralph-wiggum 插件，用 Stop 钩子堵住提前退出（/ralph-loop … --completion-promise COMPLETE --max-iterations 50）。“它不试图维持一个长命的、越来越聪明的会话。它接受：一个全新的上下文窗口才是最宝贵的资源。”

7

长时运行配方（Anthropic，2025 年 11 月）

“想象一个由轮班工程师组成的软件项目，每个新工程师到岗时对上一班发生了什么一无所知。”初始化 agent（只跑一次）：init.sh、feature-list.json（200+ 特性、全部 passes:false）、初始提交。编程 agent（反复跑）：每会话只做一个特性、跑测试、更新 claude-progress.txt、写描述性提交。细节皆有出处：特性清单用 JSON 不用 Markdown（agent 会把 Markdown 写坏）；永不删除或修改测试；浏览器自动化（Puppeteer MCP）对 bug 发现的提升“显著”于只看代码级测试。

8

OpenAI 的 Codex 配方（Ryan Lopopolo，2026 年 2 月）

3 名工程师、约 5 个月、约 100 万行、约 1,500 个 PR、零行手写。教训：巨大的 AGENTS.md 挤占了任务上下文且迅速过期——改为约 100 行的地图，指向结构化的 docs/ 树；架构规则写成代码（依赖分层、导入方向错了就让构建失败的结构测试、由 Codex 自己写的 linter）；每个 git worktree 一个可启动的应用；本地日志 / 指标 / 轨迹；agent 之间互评。“人负责掌舵，agent 负责执行。”“agent 不需要更多指令。它需要一个世界：在那里做对的事显而易见，做错的事很难。”

9

成本与延迟的共识打法

按任务路由（强模型规划、廉价模型执行）；子 agent 与 worktree 都要花 token 与审查带宽；用压缩对抗无限拉长的上下文（上下文越长质量越掉，即“上下文腐烂”）；任何步骤能写下来的任务，用工作流（workflow）胜过用 agent（固定调用、固定上下文、可测试——而 agent 的方差是负债）。Codex 的 JS 运行器与 Stagehand 的树剪枝，本质上都是 token 效率型的 harness 设计，不是模型进步。

可直接抄的五条小贴士

失败优先的 AGENTS.md

从最小开始（概览 + 技术栈）。每一次真实翻车，沉淀成一条锋利的约束，并路由到正确的层（指令 / 钩子 / 工具 / 技能）。不写愿望式条目。—— Hashimoto

一次只做一件事

“这东西一次只擅长做一件事”（Lada Kesseler）。强制手段放在独立的窄通道里，而不是把指令文件写得更长；技能的描述是写给 agent 做调用决策的，不是写给人看的——描述太泛、互相重叠，agent 就选不出来。

子 agent 的输出纪律

子 agent 把产物写到磁盘，只返回路径 + 一行摘要；编排者的上下文保持干净。—— 社区长时运行经验

薄的垂直切片

Dex Horthy（HumanLayer）：把规划前置（需求 → 架构 → 程序设计 → 垂直切片），交付约 100–200 行、人能 curl / 点击 / 审查的曳光弹，而不是几千行的横向 PR；约 40% 的任务保持一次到位即可。

评测集从 10 个任务起步

“无聊但决定性”——每次改提示 / 模型 / 工具都跑一遍。没有它，每次微调都会让演示变好、同时悄悄弄坏另外两个任务。

权限写成数据，安全不交给模型

不要把模式写死在代码里：用声明式 allow / ask / deny 规则集表达行为，让模式自然涌现（OpenCode 的 plan 模式、Gemini 的 TOML 策略）。沙箱（操作系统 / 容器）与审批策略是两个独立的层；只靠提示词的安全“在每个演示里都成立，在第一次注入时就倒下”。Pi 与 Hermes 的诚实原则：没有操作系统沙箱，就明说没有。

SECTION 08

给独立开发者的方案：抄什么、避什么、怎么起步

一句话版：从一个现成的薄 harness 起步（fork Pi 或 Deep Agents，或直接配置 OpenCode / Codex），在写任何“聪明”代码之前，你自己的代码应该不超过 500 行的循环 + 工具。

按优先级抄这 10 条

  • 薄循环、厚技能。一个循环文件；技能是文件夹（SKILL.md + 脚本 + 参考资料），只在触发时加载，描述要具体到 agent 能据此做选择。两周没被触发过的技能，删。
  • 少量通用工具，类型明确、失败安全。read / write / edit / bash（外加一个搜索、一个测试运行器）胜过 40 个窄工具。每个工具：职责单一、输入有类型、明确区分“查询失败”与“无数据”、失败要安全。
  • 文件 + git 即状态。PROGRESS.md、feature-list.json（false → true）、init.sh、描述性提交。它扛得过压缩、崩溃与换会话——同时就是你的审计轨迹。长任务每会话一个特性、每个工作单元一个新窗口（Ralph 式）。
  • 必须发生的事用确定性钩子。每次编辑后格式化 / lint、阻断写受保护路径、测试不过 + 完成承诺未出现就不许退出。永远不要靠系统提示保安全。
  • 先沙箱，后凭据。操作系统沙箱（Docker / Seatbelt / bubblewrap），至少也要一次性 VM + 独立 worktree + 最小权限 token。永不给常驻 agent 你的主 shell + 主凭据。
  • 独立验证者。第二个 agent（全新上下文，最好换一个更便宜或不同的模型）跑测试、读 diff，只能给出带证据的 PASS / FAIL。高层测试放在作者 agent 改不到的地方。
  • 评测集从第一天就有。10 个真实任务，断言的是预期效果而非预期文本。每次改提示 / 工具 / 模型都跑。除了通过率，还要报“每个成功任务的成本”与“每任务步数”。
  • 模型路由 + 预算。强模型做规划与审查，便宜快的做实现与搜索；按会话的 token 预算要能阻断；步数上限 + 重复检测 + 最大迭代阀。按任务计量 token——压缩、树剪枝、JS 运行器式组合这类 harness 改动， routinely 胜过换模型。
  • 可观测性当功能做。只追加的运行日志（工具、参数、结果、token、allow/deny）。不能重放一次运行，就修不了它。
  • Pi 的 <1k token 系统提示，是你要挑战的预算线。

避开这些

  • 只靠提示词的权限（“对生产环境小心点”），以及在一次性容器之外使用跳过权限式的 bypass。
  • 四大反模式：工具动物园、无限上下文自助餐、杀不死的会话、无评测的调参——每一个都“看起来像进展”，每一个都是日后的事故。
  • 单 agent 还没可靠就搞多 agent 扇出。子 agent 会成倍放大成本、藏匿失败（级联幻觉）、让审查更难。加子 agent 是为了隔离（如无副作用的网络检索），不是为了并行的排场。
  • 自我打分与未经审查的自写技能。从一次幸运运行蒸馏出的技能、或 agent 能改的测试集，都会给自己的错误发合格证。
  • 按星数购物。看许可（Crush 的 FSL 与 MIT 之别、若干项目的非 OSI 许可）、看活跃度（Aider 停滞、Gemini CLI 消费者关停、Roo Code 归档）、看默认设置——不是看星。
  • 把检索内容当指令。网页、issue、文件、粘贴内容都是数据。隔离检索，副作用要审批。

第一周计划

  • 第 1 天：Pi 或 OpenCode 在容器里对着一个仓库跑起来。
  • 第 2 天：AGENTS.md 失败日志 + pre / post 钩子。
  • 第 3 天：特性清单 + Ralph 式循环，跑完一个数小时量级的任务。
  • 第 4 天：验证者 agent + 10 个任务的评测集。
  • 第 5 天：token / 成本日志 + 一次模型路由决策（规划者 vs 执行者）。
  • 做完这些，才考虑第二个 agent。
